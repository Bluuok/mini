# STAR Bullet Writing Contract

每条简历 Bullet 都必须由“黑体摘要 + 一段连续的自然语言 STAR 支撑”组成。STAR 只是写作骨架，简历区不得打印 `S/T/A/R` 标签，也不得拆成四行或四段：

- **S（Situation）**：触发任务的具体背景、异常或约束。
- **T（Task）**：候选人需要解决的目标，不把业务背景重复当成任务。
- **A（Action）**：候选人采取的工程动作、决策和具体 Artifact；要写出 Agent 层、实现方式与可展示对象。
- **R（Result）**：动作带来的可验证结果、交付物或可观察状态；有真实数字才写数字，没有数字就写可验证的 Schema、Trace、状态门禁或任务结果，不编造业务指标。

推荐的简历表达：

```text
**[核心技术 / Artifact]** 面对[情境]，任务是[目标]；通过[工程行动与实现]，最终[结果或可验证产物]。
```

黑体摘要必须让招聘者直接识别核心能力；四个要素要在同一段话中自然衔接，结果必须对应前面的行动，不能只写“提升效率”“增强稳定性”等空泛结论。审查区再逐项回填四要素。

场景状态、Ownership、Claim 和证据边界只放在后续审计区，不放进每条简历 Bullet；简历 Bullet 使用与事实相符的“设计、构建、验证、运行”等动词，不能用审计提示语替代结果。
