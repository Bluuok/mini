# MiniCode 简历要点库（付费版）

## 使用说明

从下面 `R01` 到 `R25` 中选择 4-5 个点写进简历。不要全写。每个点都标注了适合人群、掌握门槛、面试风险和对应 Q&A。

等级说明：

- 基础：适合项目经验少、只想稳妥写的人。
- 进阶：适合能讲清模块设计和数据流的人。
- 高阶：适合能承受源码级追问的人。

## R01 Agent Loop 执行闭环

- 等级：进阶
- 适合：AI 应用开发、Agent 工程、后端工程
- 简历写法：针对多轮编码任务中模型推理与工具调用缺乏统一编排、长任务易中断的问题，基于模型-工具-模型循环的 Agent 执行模式，设计了以 `runAgentTurn` 为核心的执行循环（协调模型推理、工具调用、结果回填与终止检查），实现了多轮编码任务的稳定闭环执行。
- 能讲什么：用户输入如何进入 Agent Loop；模型如何返回 `assistant` 或 `tool_calls`；工具结果如何追加回消息历史；什么时候终止。
- 掌握门槛：能画出“用户输入 -> 模型推理 -> 工具执行 -> tool_result -> 下一轮模型推理”的闭环。
- 面试风险：如果讲不清 `tool_calls` 和 `tool_result` 的反馈关系，不要写成核心亮点。
- 对应 Q&A：`Q01.1`、`Q01.2`、`Q01.3`
- CodeWiki：`W01`

## R02 Agent Turn 状态机与边缘恢复

- 等级：高阶
- 适合：Agent 架构、AI Infra、工程稳定性方向
- 简历写法：针对 Agent 单次请求无法表达进度、空响应与思考中断等异常导致任务悬挂的问题，基于状态机建模，设计了 Agent Turn 状态机（覆盖 assistant 消息、进度更新、工具调用、空响应恢复、可恢复思考中断与最大步数终止），实现了长链路任务的异常可恢复。
- 能讲什么：为什么 Agent 不是一次请求；为什么要区分 progress 和 final；空响应和 thinking stop 如何恢复。
- 掌握门槛：能解释 `emptyResponseRetryCount`、`isRecoverableThinkingStop`、`maxSteps` 的作用。
- 面试风险：这是源码级点，适合能讲清循环状态的人。
- 对应 Q&A：`Q02.1`、`Q02.2`、`Q02.3`
- CodeWiki：`W01`
