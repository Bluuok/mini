# MiniCode 简历组合方案（付费版）

## 使用说明

如果会员不知道怎么选，直接从下面方案中选一套。每套只建议写 4-5 个点。写得越多，面试风险越高。

每套都包含：

- 推荐人群
- 推荐 `Rxx` 组合
- 项目简介
- 简历 bullet 示例
- 面试准备重点

## 方案 A：基础保守版

### 推荐人群

适合项目经验少、刚开始接触 Agent、担心被源码深挖的会员。

### 推荐组合

- `R01` Agent Loop 执行闭环
- `R08` ToolDefinition 与 ToolRegistry
- `R09` 内置文件与搜索工具
- `R10` 写入前审查与 Diff 流程
- `R22` 轻量可追溯的 Claude Code 参考实现

### 项目简介

参考 Claude Code 的核心交互模式，实现一个轻量级终端 AI Coding Agent，支持工作区感知、工具调用、文件读取搜索、安全写入审查和多轮任务执行。

### 简历 bullet 示例

- 针对多轮编码任务中模型推理与工具调用缺乏统一编排、长任务易中断的问题，基于模型-工具-模型循环的 Agent 执行模式，设计了以 `runAgentTurn` 为核心的执行循环（协调模型推理、工具调用、结果回填与终止检查），实现了多轮编码任务的稳定闭环执行。
- 针对模型输出到安全函数调用之间缺乏契约与校验的问题，基于 JSON Schema 与注册表模式，设计了统一 `ToolDefinition`/`ToolRegistry` 契约（工具描述、参数校验、运行时验证与执行句柄），实现了工具调用的安全落地与统一调度。
- 针对 Agent 观察代码库时无界读取与搜索导致上下文失控的问题，基于受控观察设计，设计了工作区感知的文件/搜索工具（目录列举、分页读取、ripgrep 搜索、路径安全与输出上限），实现了 Agent 观测行为的受控。
- 针对 Agent 直接写盘存在误改与静默破坏风险的问题，基于 diff 审查与审批流设计，设计了写前审查流程（所有文件修改生成统一 diff，审批通过后才落盘），实现了文件写入风险的可控。
- 针对 Agent 学习型项目难以作为可信简历落点的问题，基于轻量级参考实现思路，设计了可追溯的 Claude Code 风格 Coding Agent 参考实现（聚焦工作区感知、工具使用、安全审查、上下文治理与终端 UX），实现了核心交互模式的可验证复现。

### 面试准备重点

重点准备 `Q01`、`Q08`、`Q09`、`Q10`、`Q22`。这套方案不要主动讲 MCP、上下文压缩和复杂权限生命周期。

## 方案 H：Web 信息能力版

### 推荐人群

适合想在简历中体现 Agent 外部信息获取能力，或目标岗位涉及搜索/信息检索/知识增强的会员。

### 推荐组合

- `R20` Web Search / Web Fetch 工具
- `R08` ToolDefinition 与 ToolRegistry
- `R10` 写入前审查与 Diff 流程
- `R01` Agent Loop 执行闭环
- `R18` 会话持久化、恢复与分支

### 项目简介

实现一个支持本地工作区与外部信息联合感知的 AI Coding Agent，在文件工具和搜索工具基础上，通过 Web Search / Web Fetch 为 Agent 提供代码库之外的上下文扩展能力，配合写入审查与会话持久化形成可追溯的开发辅助闭环。

### 简历 bullet 示例

- 针对网页内容无界进入上下文导致污染与成本问题，基于工具边界与内容控制设计，设计了 `web_search`/`web_fetch` 工具（域名过滤、可读性提取、重试退避、超时与截断），实现了外部信息获取的受控。
- 针对模型输出到安全函数调用之间缺乏契约与校验的问题，基于 JSON Schema 与注册表模式，设计了统一 `ToolDefinition`/`ToolRegistry` 契约（工具描述、参数校验、运行时验证与执行句柄），实现了工具调用的安全落地与统一调度。
- 针对 Agent 直接写盘存在误改与静默破坏风险的问题，基于 diff 审查与审批流设计，设计了写前审查流程（所有文件修改生成统一 diff，审批通过后才落盘），实现了文件写入风险的可控。
- 针对多轮编码任务中模型推理与工具调用缺乏统一编排、长任务易中断的问题，基于模型-工具-模型循环的 Agent 执行模式，设计了以 `runAgentTurn` 为核心的执行循环（协调模型推理、工具调用、结果回填与终止检查），实现了多轮编码任务的稳定闭环执行。
- 针对会话中断丢失、无法恢复与复现的问题，基于 JSONL 事件流存储，设计了会话持久化机制（事件流记录、resume 恢复、fork 分支、压缩边界与自动清理），实现了会话的可恢复与可审计。

### 面试准备重点

重点准备 `Q20`、`Q08`、`Q10`、`Q01`、`Q18`。注意不要把 Web Fetch 夸大成爬虫系统，强调它是受控的信息获取工具。

## 方案 B：AI 应用开发版

### 推荐人群

适合目标岗位是 AI 应用开发、LLM 应用工程、Agent 应用工程的会员。

### 推荐组合

- `R01` Agent Loop 执行闭环
- `R04` 系统提示词构建
- `R06` 分层上下文压缩
- `R13` MCP Host 集成
- `R15` Skills 渐进式加载系统

### 项目简介

实现一个终端 AI Coding Agent，围绕 Agent Loop、系统提示词、工具调用、MCP 扩展、Skills 渐进加载和上下文压缩构建可扩展的 Agent 应用架构。

### 简历 bullet 示例

- 针对多轮编码任务中模型推理与工具调用缺乏统一编排、长任务易中断的问题，基于模型-工具-模型循环的 Agent 执行模式，设计了以 `runAgentTurn` 为核心的执行循环（协调模型推理、工具调用、结果回填与终止检查），实现了多轮编码任务的稳定闭环执行。
- 针对 Agent 运行缺乏能力边界约束、上下文信息零散注入的问题，基于系统提示词工程，设计了系统提示词装配流程（注入权限上下文、Skills 摘要、MCP 状态、记忆文件与响应协议），实现了每轮执行前能力边界的一致注入。
- 针对长会话 token 无限增长导致成本上升与上下文质量劣化的问题，基于分层压缩策略，设计了四层上下文压缩（microcompact、context collapse、snip compact 与 auto compact），实现了长会话 token 增长的受控。
- 针对外部 MCP 能力接入缺乏统一入口、工具命名冲突的问题，基于 MCP 协议与命名空间隔离，设计了 MCP 外部能力层集成（stdio/HTTP 服务工具包装为内部 ToolDefinition），实现了外部工具与内置工具的统一调度。
- 针对全量加载 Skills 导致上下文浪费与启动变慢的问题，基于渐进式加载设计，设计了 Skills 渐进式加载机制（仅暴露名称/描述摘要，任务触发时按需加载完整 `SKILL.md`），实现了扩展能力与上下文成本的平衡。

### 面试准备重点

重点准备 `Q01`、`Q04`、`Q06`、`Q13`、`Q15`。如果 `R06` 讲不稳，可以替换为 `R05`。

- `R14` MCP 配置、Token 与协议缓存

### 项目简介

实现一个面向本地开发工作流的 AI Coding Agent 后端基础设施，重点设计工具注册表、权限管理、会话持久化、配置合并和 MCP 服务管理能力。

- 针对多 MCP 服务配置分散、连接建立开销大的问题，基于配置合并与协议缓存，设计了 MCP 服务管理体系（用户/项目配置合并、远程 token 独立存储、协议协商与协议缓存），实现了 MCP 连接建立的加速。

### 面试准备重点

重点准备 `Q08`、`Q12`、`Q18`、`Q19`、`Q14`。这套方案适合讲工程设计，不要过度强调模型效果。

## 方案 D：CLI 工具链版

### 推荐人群

适合开发者工具、CLI 工具、终端产品、工程效率方向会员。

### 推荐组合

- `R09` 内置文件与搜索工具
- `R11` Shell 执行与后台任务
- `R16` TUI 全屏交互与 ScreenState
- `R17` Slash Commands 与本地工具快捷方式
- `R21` 响应协议与进度消息

### 项目简介

实现一个终端优先的 AI Coding Agent，重点优化开发者在 CLI 环境下的交互体验，支持本地文件工具、Shell 执行、全屏 TUI、Slash Commands 和实时进度反馈。

### 简历 bullet 示例

- 针对 Agent 观察代码库时无界读取与搜索导致上下文失控的问题，基于受控观察设计，设计了工作区感知的文件/搜索工具（目录列举、分页读取、ripgrep 搜索、路径安全与输出上限），实现了 Agent 观测行为的受控。
- 针对 Agent 执行任意命令带来的安全与失控风险，基于命令风险分级与权限检查，设计了受控 Shell 执行（命令归一化、shell 片段检测、风险分类、权限审批与后台任务追踪），实现了高危命令的可拦截。
- 针对终端 Agent 长任务期间缺乏可视化反馈、交互体验差的问题，基于状态驱动重绘，设计了全屏 TUI 交互层（`ScreenState` 管理对话、工具动态、上下文统计与权限弹窗），实现了终端交互体验的工程化。
- 针对确定性操作走模型推理导致延迟高、响应不稳定问题，基于本地工具直连设计，设计了斜杠命令与本地快捷键（`/read`、`/grep`、`/cmd` 直接映射确定性工具），实现了常用操作的即时可靠响应。
- 针对长任务执行期间用户缺乏进度感知、误判卡死的问题，基于进度/最终响应分离协议，设计了 progress/final 响应协议（长任务持续反馈状态、中间消息不终止轮次），实现了长任务的进度可感知。

### 面试准备重点

重点准备 `Q09`、`Q11`、`Q16`、`Q17`、`Q21`。如果岗位偏后端，可以把 `R21` 换成 `R18`，同时面试准备重点从 `Q21` 改为 `Q18`。

## 方案 E：Agent 架构高阶版

### 推荐人群

适合对 Agent 架构、LLM Infra、上下文治理理解较深的会员。

### 推荐组合

- `R02` Agent Turn 状态机与边缘恢复
- `R03` Model Adapter 抽象
- `R05` Token 估算与上下文监控
- `R06` 分层上下文压缩
- `R07` 大型工具结果外置化

> ⚠️ 注意：本方案包含 3 个高阶点（R02、R06、R07），超出使用指南中「最多 1-2 个高阶点」的建议。仅适合能独立面对源码级追问、能解释完整数据流和设计取舍的会员。如果任一高阶点讲不稳，优先降级为对应的进阶点。

### 项目简介

实现一个注重长任务稳定性的 AI Coding Agent 执行引擎，围绕模型适配、轮次状态机、上下文监控、分层压缩和大型工具结果外置化提升复杂任务下的可持续执行能力。

### 简历 bullet 示例

- 针对 Agent 单次请求无法表达进度、空响应与思考中断等异常导致任务悬挂的问题，基于状态机建模，设计了 Agent Turn 状态机（覆盖 assistant 消息、进度更新、工具调用、空响应恢复、可恢复思考中断与最大步数终止），实现了长链路任务的异常可恢复。
- 针对 Agent Loop 直连具体模型 SDK 导致核心逻辑耦合、难以测试的问题，基于适配器抽象，设计了 `ModelAdapter` 模型适配层（统一消息转换、响应解析与 mock 测试），实现了核心循环与模型供应商的解耦。
- 针对长会话上下文消耗不可见、压缩决策缺乏量化依据的问题，基于 Provider usage 统计与本地 token 估算，设计了上下文监控机制（双路用量统计与利用率分级），实现了压缩触发决策的量化驱动。
- 针对长会话 token 无限增长导致成本上升与上下文质量劣化的问题，基于分层压缩策略，设计了四层上下文压缩（microcompact、context collapse、snip compact 与 auto compact），实现了长会话 token 增长的受控。
- 针对超大工具结果挤占上下文导致关键信息丢失的问题，基于结果外置化设计，设计了大型工具结果外置机制（超长输出落盘并以预览/指针替换，保留本地可追溯性），实现了上下文占用与可追溯性的平衡。

### 面试准备重点

重点准备 `Q02`、`Q03`、`Q05`、`Q06`、`Q07`。这套方案风险最高，只建议能讲清源码流程的人使用。

- 针对会话中断丢失、无法恢复与复现的问题，基于 JSONL 事件流存储，设计了会话持久化机制（事件流记录、resume 恢复、fork 分支、压缩边界与自动清理），实现了会话的可恢复与可审计。

## 方案 I：前沿热点版（Agent 评测 / Skill 自进化 / Agent 安全）

### 推荐人群

- `R12` PermissionManager 权限系统

### 项目简介

实现一个把「评测、进化、安全」三个前沿话题落到工程实处的 AI Coding Agent：以确定性验证闭环度量改动效果、以渐进披露治理技能库、以受控执行体系守住安全边界。

### 简历 bullet 示例

- 针对 Agent 改动效果无法量化验证、回归不可见的问题，基于确定性验证信号与结构化轨迹，设计了受控验证闭环（MockModelAdapter 离线测试、diff 审查后执行测试作为验收信号、JSONL 会话轨迹回放），实现了改动效果的确定性归因与回归可追踪。
- 针对技能库规模增长导致上下文浪费、技能质量难以治理的问题，基于渐进式披露机制，设计了 Skills 分级加载体系（L1 元数据常驻、L2 全文按需加载、L3 资源按需注入，发现优先级排序），实现了扩展能力与上下文成本的平衡。
- 针对 Agent 自主执行造成误改文件与高危命令失控的问题，基于信任边界下移原则，设计了受控执行体系（写前 diff 审批、命令风险分级、权限状态机与权限上下文注入），实现了高危操作的硬拦截与最小权限落地。
- 针对权限审批状态分散、难以统一管理的问题，基于最小权限原则，设计了 `PermissionManager`（路径访问、命令执行与编辑审批，支持一次性/回合级/持久/反馈拒绝决策），实现了权限状态的生命周期化管理。
- 针对会话中断丢失、无法恢复与复现的问题，基于 JSONL 事件流存储，设计了会话持久化机制（事件流记录、resume 恢复、fork 分支、压缩边界与自动清理），实现了会话的可恢复与可审计。
