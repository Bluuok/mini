#  MiniCode 项目使用指南（付费版）

## 一句话定位

MiniCode 是一个轻量级、终端优先的 AI Coding Agent 项目。它参考 Claude Code 类产品的核心工作流，用 Agent Loop、Tool Calling、MCP、Skills、上下文压缩、权限审查、TUI 和会话管理构成一个可学习、可复现、可包装的 Agent 工程项目。

会员不要把它当成“又一个开源项目介绍”。正确用法是：

> 从 MiniCode 里选 4-5 个自己能讲清的工程亮点，组合成一段可信的 AI Agent 项目经历，再用对应 Q&A 准备面试追问。

## 推荐使用顺序

### 第一步：先确定自己的目标岗位

先选一个主方向：

- AI 应用开发：突出 Agent Loop、Tool Calling、上下文管理、MCP/Skills。
- 后端工程：突出工具注册表、配置系统、权限系统、会话持久化。
- 工具链/CLI：突出 TUI、Slash Commands、本地工具快捷方式、Shell 执行和后台任务。
- Agent 架构：突出模型 适配器、系统提示词构建、上下文压缩、扩展体系。
- 基础保守：只写最容易讲清的项目结构、工具调用、安全审查和会话管理。

### 第二步：在要点库中选 4-5 个点

进入 `02-MiniCode简历要点库-付费版.md`，按下面规则选：

- 至少 2 个基础或进阶点，保证能讲清。
- 最多 1-2 个高阶点，避免面试被深挖时失控。
- 不要只选同一类点，例如全部都是上下文压缩或全部都是 TUI。
- 每个点都要能说出“为什么这么设计”和“解决了什么问题”。

建议组合：

- 1 个项目总架构点。
- 1 个工具调用或扩展点。
- 1 个上下文或会话治理点。
- 1 个安全、权限或工程稳定性点。
- 可选 1 个岗位特色点。

### 要点类别速查

「不要只选同一类点」的前提是知道哪些点属于同一类。下面按工程领域分类：

| 类别 | 对应 R 点 |
| --- | --- |
| Agent 执行核心 | R01, R02, R03, R04, R21 |
| 工具与扩展体系 | R08, R09, R13, R14, R15, R17, R20 |
| 上下文治理 | R05, R06, R07 |
| 安全与权限 | R10, R11, R12 |
| 交互与基础设施 | R16, R18, R19, R22 |

建议从至少两个不同类别中选点，避免全部落在同一类别。

### 第三步：用 Q&A 做反向筛选

每选一个 `Rxx`，马上去 `03-MiniCode项目面试Q&A-付费版.md` 找对应 `Qxx.x`。

如果你看完 Q&A 后发现：

- 完全不知道在问什么：不要写这个点。
- 只能背答案，但不能画流程：谨慎写。
- 能解释设计取舍和失败场景：可以写进简历。

### 第四步：套用组合方案

如果不知道怎么组合，直接看 `04-MiniCode简历组合方案-付费版.md`。

优先使用默认套餐，不要一开始就追求“高大上”。简历项目的目标不是堆术语，而是让面试官追问时你有话可讲。

### 第五步：生成自己的简历版本

一段完整项目经历建议包含：

- 项目名：MiniCode / AI Coding Agent / 终端智能编程助手。
- 项目简介：1-2 句话说明项目是什么。
- 技术栈：TypeScript、Node.js、LLM Tool Calling、MCP、TUI、JSONL、Agent Loop 等。
- 技术亮点：4-5 条 bullet。

不要把所有亮点都写进去。写得太多，面试官会默认你都能讲。

## 简历 bullet 写法

推荐结构：

> 设计/实现 + 技术模块 + 解决的问题 + 具体机制 + 结果或价值

例子：

> 设计基于 model-tool-model 的 Agent 执行循环，通过 `runAgentTurn` 编排模型推理、工具调用、工具结果回传和终止判断，支持多轮任务执行、空响应重试、可恢复 thinking stop 与上下文维护，提升长任务执行稳定性。

不推荐：

> 熟悉 Agent Loop、Tool Calling、MCP、上下文压缩、安全权限等。

问题是太空，面试官不知道你到底做了什么，也很容易被追问穿。

## 选点自检表

每个点写进简历前，问自己 5 个问题：

- 这个点解决了什么实际问题？
- 它在 MiniCode 里对应哪个模块？
- 如果不用这个设计，会出现什么问题？
- 面试官问源码流程，我能不能按顺序讲出来？
- 面试官问 trade-off，我能不能说出取舍？

5 个问题里答不上 2 个以上，就不要把这个点写成核心亮点。

## 风险提示

高风险写法：

- 把“参考 Claude Code 架构”写成“实现了 Claude Code 完整能力”。
- 把“支持 MCP/Skills 扩展”写成“构建了完整插件市场”。
- 把“上下文压缩策略”写成“显著降低成本 xx%”，但没有数据。
- 把路线图中的多语言实现、未来优化写成已完成成果。

稳妥写法：

- 写“实现参考版本”“设计闭环”“支持基础能力”“完成机制拆解”。
- 用“提升稳定性”“降低上下文膨胀风险”“增强可控性”这类可解释价值，不编造量化指标。

## Agent Skill 使用方式

如果会员使用 `minicode-resume-skill`，推荐这样提问：

```
我目标岗位是 AI 应用开发，技术栈是 Java + Python，Agent 项目只了解基础 Tool Calling。
请用 MiniCode 帮我选 4-5 个适合写进简历的点，生成一版项目经历，并给出对应面试 Q&A。
```

如果要深挖某个点：

```
请围绕 R06 上下文压缩做深挖，基于 CodeWiki 解释它的触发条件、实现流程、面试追问和简历改写方式。
```

Skill 的正确行为是先读压缩资料，只有深挖时才回到完整 CodeWiki。
