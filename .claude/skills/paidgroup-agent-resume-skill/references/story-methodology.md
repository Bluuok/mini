## 2. 开发故事九阶段主线（方法论 → 叙事）

按「一个 Agent 项目是怎么按设计方法论从 0 到 1 做出来」组织整条开发故事。每个阶段给出：要回答的问题、输出产物、与 Step 1c 模块的映射。

### 阶段 0 · 问题定义与设计哲学
- 要回答：项目为什么存在？解决谁的什么问题？**明确不做什么**（取舍清单）。
- 输出：一句话定位 + 取舍表 + 「不做清单」（例：MiniCode 三条设计哲学——不为大而全、骨架清晰、为学习而生；明确未做插件市场/任务集群）。
- 映射：Module 1 事实卡（项目目标）、Module 2 业务故事、Module 5（背景）。

### 阶段 1 · 核心架构决策（骨架）
- 要回答：主循环/骨架选型（model-tool-model、ReAct、Plan-and-Execute、Host/Runner 分离……）？为什么是这个骨架而不是别的？
- 输出：一张架构图 + 一条「数据怎么流」讲解 + 骨架选型对比表（含放弃的方案）。
- 映射：Module 3 架构与数据流、Module 4、Module 8 速查。

### 阶段 2 · 能力分层设计
- 要回答：按五层地图把系统拆成哪些层？每层边界？层间接口？哪一层是「平台自带」、哪一层要「自建适配器」？
- 输出：分层图 + 每层职责一句话 + 层间接口清单 + 能力归属表。
- 映射：Module 3、Module 4、Module 8。

### 阶段 3 · 逐模块开发顺序与动因
- 要回答：先做什么、后做什么、为什么这个顺序（依赖关系/风险排序）？每个模块的「进场动因」（遇到什么问题才加它）？
- 输出：模块时间线（模块 → 动因 → 解决什么问题 → 留下什么边界）。
- 约束：动因必须来自 codewiki/源码可推断的结构依赖，个人时间线标【待确认】，不编造开发日期。
- 映射：Module 5（STAR 的行动）、Module 4、Module 7（能力演进线）。

### 阶段 4 · 关键设计决策与反例
- 要回答：对每个关键 R 点：为什么不用更简单/更复杂的方案？（why-not）
- 输出：决策表（决策 / 候选方案 / 为什么选它 / 放弃了什么）。
- 映射：Module 4 技术故事、Module 6（why 追问层）、Module 8。

### 阶段 5 · 评测与迭代闭环
- 要回答：怎么证明改动有效？确定性验证信号 vs 模型判断？怎么防回归？指标口径是什么？
- 输出：评测闭环图 + 验收信号清单 + 指标口径说明（如仓库真实测试数 vs 期望值，必须分开）。
- 映射：Module 4、Module 5（结果）、Module 6（评测维度追问）。

### 阶段 6 · 安全与治理
- 要回答：权限怎么设计（身份-资源-动作-策略-审计）？审批放哪条路径？注入怎么防？隔离做到什么程度？
- 输出：安全边界图 + 权限策略清单 + 攻击/防护对照表 + Scope Boundary 声明。
- 映射：Module 4、Module 6（安全追问）、Module 3。

### 阶段 7 · 踩坑与失败恢复
- 要回答：真实踩过哪些坑？怎么恢复？哪些是「设计失败后改的」？
- 输出：失败案例表（现象 / 根因 / 修复 / 防复发）。
- 约束：只能写 codewiki/源码里有证据的恢复机制（如 auto compact 连续 3 次失败 self-disable），不编造事故。
- 映射：Module 4（失败与恢复）、Module 6（失败维度）、Module 1（已知风险）。

### 阶段 8 · 落地与演进
- 要回答：现在能做什么、边界在哪、roadmap 上什么还没做（必须与已实现分开）？
- 输出：能力边界表（已实现 / 理解可扩展 / 前沿认知）+ 演进方向。
- 约束：roadmap/未来计划永远不写成已实现；前沿点必须带【项目实现】/【前沿认知】标注。
- 映射：Module 1 事实卡（待确认）、Module 7 多项目联动。

## 4. 方法论表达规则（增强层硬约束）

- **事实分层标签不变**：【本人实际参与】/【项目整体架构】/【待确认】全程必须使用。
- **开发顺序只讲已实现**：模块「进场动因」必须来自 codewiki/源码可推断的结构依赖；个人时间线用【待确认】，不编造日期。
- **方法论术语标注来源**：允许引用八股术语（ReAct / Plan-and-Execute / HITL / 确定性信号 / 记忆分层 / 权限五要素），但标注【方法论概念】与【项目实现】的区别；论文数字只进面试 talking points，不进开发故事正文。
- **不做清单是加分项**：明确写「项目没有做 X」（如 MiniCode 未做插件市场、HappyClaw 无原生 RAG），增强可信度。
- **能力归属**：阶段 6 只声明选中 R 点 Scope Boundary 内能力；容器隔离/网络白名单/凭据代理等归【前沿认知】。
- **评测闭环**：指标标明口径（如 290+ 测试是仓库事实），方法论期望值（如"任务成功率提升"）写为目标/预期，不写成已实现。
- **roadmap 分界**：阶段 8 的演进方向必须与已实现能力分开呈现。

## 5. 使用方式

1. Story 模式触发后：先按 `references/<项目>/workflow.md` Step 1c 输出 8 模块故事包（原样执行）。
2. 再按本文件九阶段主线组织一遍「整个项目的开发故事」，用第 3 节交叉表与 8 模块对齐。
3. 面试建议优先准备：阶段 0（定位）→ 1（骨架）→ 4（决策反例）→ 5（评测）→ 6（安全），模块 3/7 用于追问展开。
4. 若用户只想要"开发故事"（不要完整 8 模块），可直接按九阶段主线输出，并说明这是方法论增强版（原 8 模块可按需补充）。
