## 2. 简历文本

# Clawtide · 自托管数字员工工作站

基于 HappyClaw 参考架构的个人项目，以跨境电商运营为演示场景，将 IM 消息与定时任务接入 Agent 执行链，并提供 Profile 配置、工作区授权和 Web 管理入口。

**技术栈：** TypeScript、Node.js、Hono、SQLite、React、WebSocket、Claude Agent SDK。

- **任务物化与条件认领** 针对定时任务重复触发与执行记录难以追踪的问题，基于 SQLite 唯一键和条件更新，设计了 occurrence 物化、owner/token 认领及终态记录链路，实现了发生点去重与任务状态更新的条件校验。

- **Agent Profile 与配置变更** 针对数字员工规则散落、局部修改易覆盖其他配置的问题，基于四段式 Prompt 与版本快照，设计了独立字段更新、历史内容恢复和草稿短语确认入口，实现了配置分段维护与历史可回看。

- **IM 适配与会话接入** 针对不同 IM 消息格式和会话形态难以复用的问题，基于 ImChannelAdapter 与能力声明，设计了飞书、Telegram 适配及消息规范化链路，实现了渠道消息经挂载解析进入统一执行入口，其余渠道保留为骨架。

- **工作区授权与 IM 准入** 针对管理角色与资源归属混用的问题，基于所有者判定和发送者身份校验，设计了读、改、删独立授权函数与 audience_mode 准入分支，实现了管理员无所有权旁路、Home 禁删及拒绝分支不执行。

- **会话认证与登录限流** 针对 Web 管理入口的身份冒用与重复登录尝试，基于随机会话 token、HMAC 签名和进程内计数，设计了签名核验后查库、双名 Cookie 及两层限流，实现了失效会话拒绝与账号维度的尝试约束。

## 4. 选型与实际边界

Node.js/TypeScript 用于服务与异步接入；Hono 承载 HTTP 路由；better-sqlite3 管理任务、配置和身份数据；React/WebSocket 承载控制台；Claude Agent SDK 负责模型—工具循环，应用层负责入口、配置和状态。以上是源码结构的解释，不伪造“我当时比较过所有框架”的决策经历。[E06–E19]

选择 SQLite 的讲法应是：当前工程以自托管和易部署为目标，任务状态由关系表与条件更新表达。SQLite 的写入互斥不能替代多步事务，也不自动证明重启恢复或外部副作用安全。当前认领使用单条条件 UPDATE；上游事务式认领是另一实现，不能混答。[E01、E02]

这里不把 Docker 写进核心技术栈：选中范围及当前核验执行链并未证明容器沙箱。三入口都能调用同一运行时，不等于每个入口装配的 Profile、授权和会话恢复策略相同；定时执行当前未传入 Profile 提示词。[E18、E19]

## 5. 统一禁用的旧承诺

| 不再使用 | 当前可讲 |
|---|---|
| 七渠道真实接通、功能一致 | 飞书与 Telegram 有真实 SDK 适配；其他五个为骨架；连接与整链联调分别举证 |
| 多实例安全调度、外部业务绝不重复 | 发生点唯一键与条件认领；外部副作用与失租中止仍有缺口 |
| 所有非 Owner 都静默拒绝 | Owner Gate 的拒绝分支静默；everyone 普通消息可进入后续授权；保留命令暂不执行 |
| 读/改/删是三种返回状态 | 三个动作检查函数，分别返回 allow/deny |
| 修改人设都必须确认短语 | 草稿发布路径有短语确认；直接 CRUD 另有认证与归属检查 |
| 四段 Prompt 就是可执行工作流/安全策略 | 四段声明配置；代码准入与工具执行限制另行负责 |
| 三入口人设完全一致 | 执行函数共享；当前定时入口缺少 Profile 装配 |
| 通知失败自动补发 IM | 调度器 notification 当前落任务日志；IM send 失败另行记录，无完整 outbox |
| 全部自研、全部实测、生产可用 | 架构参考、实际项目实现、个人改动与真实验收分别说明 |

## 6. 一段开场

这个项目叫 Clawtide，基于 HappyClaw 的参考架构，做的是个人自托管数字员工工作站。我用跨境电商运营作为演示场景，但没有把它包装成真实商家的系统。重点不是接了多少聊天软件，而是消息和定时任务怎样进入受管理的执行链：任务先有发生点与状态记录，Profile 分段维护，Web 和 IM 分别完成身份或准入判断，再进入 SDK 执行。我的介绍会围绕调度、配置变更和入口授权展开；哪些代码是上游参考、哪些是我的改动，会用实际文件和提交说明，而不会把整个 SDK 的执行循环算作自研。
