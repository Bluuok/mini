# HappyClaw 项目使用指南（付费版）

## 一句话定位

HappyClaw 可以被包装成一个"多用户 Agent 工作台 + 企业数字员工平台"：它不是只会调模型的聊天界面，而是把 Claude Code 运行时封装成可持续运行的服务，让 Agent 通过浏览器和 7 种 IM 渠道长期在线地为团队工作，并覆盖 Agent 执行引擎、多租户安全隔离、定时任务调度、用量计费、RBAC 权限、能力治理和工程化验证。

## 推荐使用顺序

### 第一步：先确定目标岗位

不同岗位不要选同一套点：

- 企业 AI 应用 / 数字员工：优先 `R07 R14 R15 R20 R23`
- AI / Agent 架构：优先 `R01 R03 R05 R06 R15`
- 后端 / 平台工程：优先 `R13 R14 R18 R20 R08`
- 前端 / 全栈：优先 `R21 R22 R06 R18 R17`
- MCP / 工具生态：优先 `R15 R16 R17 R01 R03`
- 基础保守：优先 `R02 R13 R18 R21 R24`

### 第二步：只选 4-5 个 R 点

HappyClaw 的技术点很多，但简历不是目录。建议只写 4-5 个点：

- 1 个架构总览点：说明你理解系统边界（如 `R01` 或 `R02`）。
- 1-2 个 Agent Core 点：说明你理解 Agent 执行机制（如 `R03 R05 R06`）。
- 1 个工程化点：说明你不是只会写 demo（如 `R13 R18 R24`）。
- 1 个你最能深挖的高阶点：用来应对追问（如 `R07 R14 R20 R23`）。

### 第三步：用 Q&A 反向筛选

每选一个 `Rxx`，去 `03-HappyClaw项目面试Q&A-付费版.md` 找对应 `Qxx.x`。

如果你无法回答：

- 这个点解决什么问题？
- HappyClaw 里怎么实现？
- 为什么不直接写一个更简单的版本？
- 这个设计有什么局限？

那这个点暂时不要写，或者降级成更保守的表达。

### 第四步：套用组合方案

先从 `04-HappyClaw简历组合方案-付费版.md` 选一个方案，再替换其中 1 个不熟悉的点。

不建议自己随意混搭 8-10 个点，因为这会让面试官追问范围变大。

## 简历 bullet 写法

推荐写法：

```text
设计 7 渠道 IM 统一抽象层（IMChannel 接口 + 适配器模式），将飞书、钉钉、Telegram 等平台消息规范化为统一 JID 寻址，使 Agent 核心不感知渠道差异，支持数字员工驻场企业通讯。
```

不推荐写法：

```text
实现了最强 Agent 平台，支持所有 IM 渠道和所有企业场景。
```

好的 bullet 要满足：

- 有具体工程对象。
- 有设计动作。
- 有解决的问题。
- 不编造不可证明结果。
- 面试时能讲实现和取舍。

## 风险分级

- 低风险：架构总览、路由体系、前端架构、工程验证（`R02 R18 R21 R24`）。
- 中风险：三层模型、IM 抽象、Provider 负载均衡、Schema 迁移、Agent Profile、认证、流式输出（`R01 R07 R08 R11 R13 R15 R19 R22`）。
- 高风险：Docker 沙箱、IPC 协议、StreamEvent、出站投递、Turn 租赁、定时调度、能力治理、Agent Builder、RBAC、多租户安全（`R03 R04 R05 R06 R09 R10 R14 R16 R17 R20 R23`）。

高风险点不是不能写，但必须能讲清楚源码层设计。`R04 R16 R23` 是最高风险点，不熟就降级。

## Agent Skill 使用方式

如果使用 `happyclaw-resume-skill`，建议这样问：

```text
请使用 HappyClaw Resume Skill，根据我的背景生成一版多用户 Agent 工作台项目经历。

我的背景：
- 目标岗位：企业 AI 应用 / 数字员工 / Agent 平台
- 技术栈：TypeScript、Node.js、React、SQLite
- 熟悉：后端接口、状态管理、工程化
- 不熟：Docker 安全和 MCP 协议细节

要求：
1. 只选 4-5 个 R 点
2. 每条 bullet 标注 Rxx
3. 给出对应 Qxx 面试题
4. 标注高风险点和降级建议
```

深挖某个点时：

```text
请基于 HappyClaw CodeWiki 深挖 R14 定时任务调度器的 V2 Materialization 模式，要求解释实现路径、面试追问、误区和降级说法。
```
