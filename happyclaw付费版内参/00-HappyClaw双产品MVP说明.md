# HappyClaw 双产品 MVP 说明

## 这套产品解决什么

HappyClaw 不是一个普通的"AI 聊天界面项目"，而是一个高阶的**多用户 Agent 工作台 + 企业数字员工**平台项目。它把完整的 Claude Code 运行时封装成一个可持续运行的服务，让 Agent 通过浏览器和 7 种 IM 渠道（飞书、Telegram、QQ、钉钉、微信、Discord、WhatsApp）长期在线地为企业和团队工作。

项目同时覆盖：Agent 执行引擎（Host/Container 双模式）、多渠道 IM 集成、多租户安全隔离、定时任务调度、用量计费、RBAC 权限、Skills/MCP/Plugins 能力治理、对话式 Agent Builder、实时流式事件系统、React 19 前端架构、工程化验证体系。

这套付费版 MVP 的目标，是把 HappyClaw 包装成一个可写进简历、可讲清楚架构、可承受面试追问的高阶 Agent 平台项目。

交付分成两个产品：

1. **人读版内参**：给会员学习、选点、组合简历、准备 Q&A。
2. **Agent Skill 版**：给 Agent 使用，根据用户背景自动生成 HappyClaw 简历项目和面试准备。

## 两个产品的差异

人读版负责：

- 解释 HappyClaw 为什么能作为多用户 Agent 工作台和企业数字员工平台项目。
- 帮会员从 `R01-R24` 中选择 4-5 个最适合自己的点。
- 用 `Qxx.x` 做反向筛选，删掉讲不清楚的点。
- 给出不同岗位和掌握程度的组合方案。

Skill 版负责：

- 让 Agent 根据用户背景自动选择组合方案。
- 生成项目简介、技术栈、4-5 条简历 bullet。
- 给每条 bullet 匹配 `Rxx` 和 `Qxx.x`。
- 在用户追问深挖时，通过 `Wxx` 回到 codewiki 源材料。

## 共用编号体系

- `Rxx`：简历要点，例如 `R07 7 渠道 IM 统一抽象与适配器模式`。
- `Qxx.x`：面试问题，例如 `Q07.1 为什么要把 7 个 IM 渠道统一抽象`。
- `Wxx`：技术依据索引，例如 `W07 多渠道 IM 系统架构与消息路由`。

这个编号体系保证三件事：

- 简历 bullet 不是孤立文案，而是能对应面试题。
- 面试答案不是临场发挥，而是能对应 codewiki 源材料依据。
- Skill 输出不是凭空生成，而是能回到完整资料深挖。

## 使用边界

- 不要一次写太多点，简历里优先写 4-5 个最能讲清楚的点。
- 不要把 HappyClaw 写成自己从零实现的完整商业产品，除非用户确实有对应实践。
- 不要编造性能指标、用户量、线上收益、业务结果。
- 不要把路线图、扩展设想、未证实能力写成已实现。
- 高阶点必须能讲清楚"问题、实现、取舍、局限"，否则降级。

## MVP 成功标准

- 会员能从 `R01-R24` 中选出 4-5 个点写进简历。
- 每个点都有可练习的 `Qxx.x` 面试问题。
- Skill 能生成一版高阶 Agent 平台项目经历。
- 用户追问深挖时，Skill 能回到 `Wxx` 和完整 codewiki 源材料。
- 示例和评测记录能证明 Skill 输出符合护栏。
